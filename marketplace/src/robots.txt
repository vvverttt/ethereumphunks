# quantumphunks.com
#
# Why this file exists, and why it is this aggressive.
#
# On 2026-10-02 a sample of 100 consecutive Supabase log entries broke down as:
#
#     69  Bytespider          (ByteDance, masquerading as mobile Safari)
#     28  Reflectionbot/1.0   (reflection.ai)
#      3  real browsers
#
# 97% bots, at a measured 19,082 requests/hour. That is ~458k requests/day, which at the
# observed log-line size accounts for essentially all of the ~270-285 MB/day of Supabase Log
# Ingestion that put the project over quota.
#
# The thing that makes it expensive: this is a client-rendered Angular app, and these crawlers
# EXECUTE the JavaScript. A single bot page view fans out into REST reads of `ethscriptions`,
# `events`, `listings`, `comments` and `_global_config`, plus the attributes JSON and image
# fetches from Supabase Storage. Those requests land on kfnprbhoodmgfhqojmqp.supabase.co, which
# is a different origin we cannot put a robots.txt on — so the only place to stop them is here,
# before the app is ever handed over.
#
# Blocking these costs nothing in reach. Every named agent below is an AI-training scraper or an
# SEO backlink crawler; none of them sends users anywhere. Real search engines and the social
# card unfurlers are deliberately left fully allowed at the bottom of this file, so links still
# preview and the site stays indexed.
#
# NOTE: robots.txt is a request, not a fence. Bytespider in particular is widely reported to
# ignore it. This file is the honest signal and it handles the compliant crawlers; enforcement
# for the ones that lie about who they are has to happen at the Cloudflare edge.

# ---------------------------------------------------------------------------
# Link-preview unfurlers: full access, deliberately
# ---------------------------------------------------------------------------
# A crawler obeys exactly ONE group — its own if a matching one exists, otherwise `*`. These
# groups therefore OVERRIDE the catch-all below, including its Disallow on /details/, and that
# is the point: when somebody shares an item link in a chat, the unfurler has to fetch that
# exact /details/ URL or the preview card dies. Each of these fetches one URL per share rather
# than walking the site, so the cost is negligible and the value is visible.
#
# Note that search engines are deliberately NOT listed here. Googlebot and Bingbot fall through
# to `*` on purpose — giving them their own `Allow: /` group would exempt them from the catch-all
# and invite a crawl of all ~10,000 /details/ pages, which is the very cost this file exists to
# remove. Under `*` they still index the homepage and every collection landing page, which is
# all this app actually renders anything indexable for.

# ---------------------------------------------------------------------------
# Everyone else
# ---------------------------------------------------------------------------
# Crawling is allowed, but the routes below are pure cost with nothing to index.
#
# Every route in this app renders client-side from live chain/database state, so a crawler gets
# an identical empty shell for all of them while still triggering the full Supabase fan-out
# described at the top. /details/* alone is ~10,000 URLs of that, and the market/sales views are
# the same inventory re-sorted, so they are crawl traps rather than content.
#
# What stays crawlable is the part that is worth having in an index: the homepage and each
# collection's landing page. Those are bare top-level paths (the router's `:slug`), so they are
# reachable precisely because nothing below matches them.

User-agent: *
Crawl-delay: 10

Disallow: /details/
